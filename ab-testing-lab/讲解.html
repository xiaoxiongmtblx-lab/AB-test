AB 实验方法论：从假设检验到决策

本手册配套 ab-testing-lab 交互应用，用两个真实公开数据集（营销落地页实验 294,478 行 + Cookie Cats 游戏实验 90,189 行）走完一次规范的全流程。所有结论均由数据计算得出，无编造。

00两个真实数据集

数据集 AKaggle 经典营销 A/B（ab_data.csv）：用户分流旧页面 vs 新页面，观察购买转化。294,478 行会话，2017-01。含 3,893 行组-页不匹配、7,788 行重复用户（本身就是数据质量教学素材） 数据集 BCookie Cats 关卡实验：把强制休息门槛从 30 关移到 40 关，观察次日/7 日留存。90,189 名玩家（Woopa 团队公开发布，DataCamp 经典案例） 为什么选它们① 完全公开、可自由分发；② 一个「不显著」一个「显著」，正好覆盖两类决策；③ 双指标数据天然引出多重比较问题

01假设检验：把业务问题翻译成统计问题

四步翻译法

  1. 原假设 H₀：新页面对转化率没有影响（p_new = p_old）——默认怀疑一切变化
  2. 备择假设 H₁：有影响（p_new ≠ p_old，双侧）或只关心单方向（单侧，慎用）
  3. 选检验：比例类指标 → 双比例 z 检验 / 卡方；均值类（客单价、时长）→ t 检验；分布歪 → Mann-Whitney 或 Bootstrap
  4. 定 α：惯例 0.05。含义：若 H₀ 为真，只有 5% 概率误报「显著」（假阳性）
z = (p̂₂ − p̂₁) / √( p̂·(1−p̂)·(1/n₁ + 1/n₂) )，其中 p̂ 为合并转化率
# 应用中的实现（src/engine.py）
z, pval = proportions_ztest([x1, x2], [n1, n2], alternative="two-sided")
业务翻译练习：「新页面转化率 11.87% vs 旧页面 12.04%」→ 统计问题「这 0.17pp 的差是真实差异还是随机波动」。

02p 值的两种读法：一对一错

正确 vs 错误

表述对错原因
「p = 0.16，我们未能拒绝原假设，样本量下证据不足」✅这是 p 值的定义：在 H₀ 为真时，观察到当前或更极端数据的概率
「p = 0.16，说明新页面没有影响」❌不显著 ≠ 证明无差异。可能只是样本量不够（看 MDE）
「p = 0.04，新页面 96% 概率更好」❌p 值不是「H₀ 为真的概率」，也不是效应大小的度量
「p = 0.001 比 p = 0.04 效应大 10 倍」❌p 值只管「有没有」，效应大小看差值与 CI
营销页实验的真实结果：z = 1.40，p = 0.16——正确的结论是「本样本量下无法证明新页面更好（也无证据更差）」，而不是「新旧一样」。这两个表述在汇报时天差地别。

03置信区间与效应量：比 p 值更重要

差值的 95% 置信区间

CI = (p̂₂ − p̂₁) ± 1.96 · √( p̂₁(1−p̂₁)/n₁ + p̂₂(1−p̂₂)/n₂ )

营销页实验：差值 −0.17pp，95% CI [−0.39, +0.04]pp——区间几乎贴着 0 但仍跨 0，这就是「差一点显著」的直观形态。汇报时给 CI 而不是只给 p 值：决策者需要知道「最差可能亏多少、最好可能赚多少」。

效应量 Cohen's h

h = 2·arcsin√p₂ − 2·arcsin√p₁。比例数据的标准化效应量，是功效计算的通用语言。经验参考：h < 0.2 小、0.5 中、0.8 大。本实验 h ≈ 0.01——即使真实存在，也是极小的效应。

顺序建议：先看效应量是否业务上有意义，再看 CI 是否远离 0，最后才看 p 值。p 显著但效应量小到无意义的实验，一样不值得上线。

04功效与样本量：先算后跑

三个量的铁三角

量含义典型设定
α（假阳性率）H₀ 为真时误报显著的概率0.05
β（假阴性率）H₁ 为真时漏检的概率0.20（即功效 80%）
MDE（最小可检测差异）希望可靠检出多小的差异业务最小有意义值

三个量 + 基线率互相锁定，任意定死三个，第四个就被确定了。实验设计 = 在成本约束下做这道四元方程。

本数据的实算

  • 基线 12%、MDE 1pp、α=0.05、功效 80% → 每组约需 17,164 样本
  • 本实验实际每组 144,319 → 80% 功效下 MDE ≈ 0.34pp——即「连 0.34pp 的真实差异都大概率检得出」；实际差 0.17pp 仍不显著 → 有较强证据表明真实差异极小
  • Cookie Cats 每组约 45,000 → MDE 约 0.6pp 量级，足够检出 7 日留存的 0.6pp 显著差异
# 事前功效分析（应用「实验设计器」页）
h = |2·arcsin√(p+mde) − 2·arcsin√p|
n = NormalIndPower().solve_power(effect_size=h, power=0.8, alpha=0.05)
「事后功效」的陷阱：基于观测效应量算功效与 p 值一一对应，不提供新信息。真正有用的是事前功效分析——这也写在引擎的注释里。

05SRM：实验有效性的第一道闸门

Sample Ratio Mismatch（样本比例失衡）：预期 50:50 分流，实际观测 47:53——哪怕只偏一点，也说明分流系统或数据管道有问题，此时一切检验结果都不可信（偏差与结果相关性会造成虚假显著）。

检测方法：卡方拟合优度，α = 0.001

χ² = Σ (观测ᵢ − 期望ᵢ)² / 期望ᵢ，自由度 = 组数 − 1

为什么用 0.001 而不是 0.05？因为 SRM 检验的代价不对称：误报（重跑实验）成本低，漏报（带着污染数据决策）成本极高——所以宁可错杀。

本数据实况

原始数据 147,202 vs 147,276（p=0.89 ✓）；清洗后 144,319 vs 144,316（p=0.995 ✓）——两个数据集都通过了 SRM，可以放心检验。而清洗掉的 3,893 行「组-页不匹配」正是新手最常忽略的分流故障信号。

06peeking：中途偷看 p 值的代价

每天看一次 p 值，「显著了就停、不显著继续跑」——这是最常见的 AB 作死姿势。名义 α=5% 的实验，若允许在 30 个检查点任意停止，实际假阳性率可膨胀到 30%+。

用真实数据重演（应用「深入分析」页）

把营销页实验按时间重放：25 个检查点的 p 值在 0.15 ~ 0.94 间游走。想象一个实验员在第 2 天看到 p=0.30 就想「再跑跑」，第 20 天看到 p=0.15 就想「差不多了吧」——每个「想停就停」的决策都在偷走统计效力。

正确做法

  1. 事前定死样本量/时长，跑满再判（最简单、最常用）
  2. 若必须中途决策：用序贯检验（O'Brien-Fleming 等边界随时间收紧）或贝叶斯方法（后验概率 + 预期损失）
  3. 绝对禁止：无边界地反复看 p 值 + 手动停

07多重比较：看得越多，撞得越假

同时检验 m 个指标，「任何一个显著就宣称实验有效」——假阳性率从 α 膨胀为 1−(1−α)^m。两个指标就是 1−0.95² ≈ 10%，翻倍。

校正方法规则特点
Bonferronip_adj = min(p·m, 1)最保守，任何场景都稳
Holm（step-down）最小 p 乘 m、次小乘 m−1……逐步向下普遍优于 Bonferroni，推荐默认
序贯门控先验定指标优先级，一个一个按序检验业务常用：主指标过了才看次指标

Cookie Cats 实况

次日留存 p≈0.076、7 日留存 p≈0.0016。Holm 校正后：7 日留存仍显著（p≈0.0032），次日留存不显著。结论清晰表述为：「门槛后移未发现对次日留存有影响，但显著降低了 7 日留存（约 0.6pp）」——不砍掉非显著指标的报告义务，也不让显著指标被平均。

08分层稳健性：防辛普森悖论

总体差异可能被子群结构掩盖或反转（辛普森悖论）。规范动作：把核心结论按关键维度分层复核——方向一致则稳健，出现反转必须重新归因。

应用在 Cookie Cats 深入分析页内置了按活跃度（0 轮 / 1-29 轮 / 30+ 轮）分层的 7 日留存对比：各层方向与总体一致（对照 ≥ 实验）→ 支持总体结论。同时展示了该数据的著名脏点：一名玩家 14 天玩了 49,854 轮——分布严重右偏时均值不可比，所以主指标选择留存率（比例）而非轮次均值。

其他常见分层维度：新老用户、平台、渠道、时间段（周一 vs 周末）。分层后样本量变小，注意每层自身的检验功效。

09常见作死清单（自查表）

作死行为后果正确姿势
不查 SRM 直接检验分流污染 → 假显著先跑卡方 SRM（α=0.001）
中途看 p 值就停假阳性膨胀数倍事前定样本量；或序贯/贝叶斯
多指标不校正撞显著概率大增Holm 校正 / 主次指标门控
把「不显著」说成「无差异」错误决策（放弃改进）报 MDE：「能检出 X 以上差异」
用均值比较右偏数据被极端值带偏中位数/分位/比例指标
实验组用户重复出现身份泄漏按用户去重 + SRM 复查
只看总体不看分层辛普森悖论反转结论关键维度分层复核
运行 3 天就下结论新奇效应 + 周期性偏差跑满至少 1-2 个完整周期

10两个实验的完整结论（可直接引用）

实验 A：新落地页能否提升购买转化？

样本清洗后 144,319 vs 144,316（SRM 通过；剔除 3,893 行组页不匹配 + 3,895 行重复用户） 结果对照 12.04% vs 实验 11.87%，差 −0.17pp，95%CI [−0.39, +0.04]，z=1.40，p=0.16 结论在 α=0.05 下未能拒绝原假设。样本量支撑 MDE≈0.34pp，故有较强证据表明真实差异即使存在也小于 0.4pp。业务建议：新页面无足够证据支持全量上线；若切换成本极低可保持，否则维持现状

实验 B：门槛后移（30→40 关）对留存的影响？

样本45,189 vs 45,100（SRM 通过） 次日留存44.82% vs 44.23%，p≈0.076，Holm 校正后不显著 7 日留存44.79% vs 44.20%（差约 −0.6pp），p≈0.0016，Holm 校正后仍显著 结论门槛后移造成玩家更晚遭遇强制休息，短期（次日）影响不显著，但显著降低 7 日留存——休息机制更早出现反而利于长期留存。建议维持 30 关门槛
注意结论的措辞结构：样本 → 数字 → 统计判断 → 业务含义 → 建议。五个零件一个不少，且每个数字都能在应用里复算。

工程亮点（也是教学点）

  1. 聚合优先架构：清洗不物理删行而是打标志列（valid/first_user），一切统计经 groupby 聚合得出——可审计且内存友好
  2. 结论与代码分离：文案由数字模板生成，杜绝「先有结论再找数字」
  3. 蒙特卡洛交叉验证：模拟功效 vs 解析公式互相印证（0.986 vs 0.990），教「如何验证自己的统计工具」
  4. 诚实边界：事后功效、模拟数据、情景估计均明确标注局限，不冒充真实结论
